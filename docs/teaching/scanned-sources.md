# 扫描 PDF 的识别核对

在“教学准备”选择知识库后，可上传或替换 PDF，刷新处理状态并打开“核对当前识别”。处理未结束或局部识别失败时仍可逐物理页查看原页图、识别文本和缺口；文件物理页从 1 开始，与课本印刷页码不同。

处理完成后，确认知识版本，再打开文件的“逐页核对”。每页状态含义：

- 缺口：没有识别行、识别失败、空文本或重复页面，不能人工确认为完整。
- 公式缺口：检测到了替换字符、无法识别标记、部分公式定界符或花括号残缺，必须替换资料或排除该页。
- 待人工核对：有文本，但仍须教师对照原页检查文字、符号、公式和遗漏。
- 已人工核对：记录了原页核对依据，记录仅对确切知识版本、来源 ID、识别正文和覆盖警告的指纹有效。

自动检查只发现有限的格式和覆盖问题，不验证导数计算或教学内容的数学正确性。人工核对不会删除原警告，也不会补出缺失正文。图片和文本中的指令按资料原文显示，不扩大工具或资料访问权限。

核对后可“选材范围仅保留此页”，或填写开始/结束物理页排除问题范围，再保存新的固定选材。包含失败页、空结果或公式缺口的范围保持“来源待核查”。已保存选材和核对凭据保持原样；后来核对来源不会修改历史选材，需重新保存才能采用新凭据。固定来源中的折叠面板可重看原页及当前版本核对记录。

## 接口与权限

- `GET /teaching/ocr/files/{fileId}`：上传文件当前逐页状态。
- `GET /teaching/ocr/versions/{versionId}/files/{fileId}`：固定就绪版本逐页状态。
- 在上述路径后加 `/pages/{physicalPage}/image`：受保护的原页 PNG data URL。
- `POST /teaching/ocr/versions/{versionId}/files/{fileId}/pages/{physicalPage}/reviews`，正文 `{ "note": "核对依据" }`：保存人工核对。

所有入口使用当前登录用户并验证文件/版本归属。原始文件存储地址不暴露给页面；原 PDF 无法读取时明确报错，不能拿其他文件或其他页面替代。历史版本只有目录而没有可下载原文件定位时，需要重新固定资料。

## 回归与证据边界

`TeachingOcrHttpTest` 通过公开 HTTP 和实际 PostgreSQL 验证完整页列表、持久化核对、内容指纹失效、固定选材保持和越权拒绝。`ScannedPdfSourceHttpTest` 创建真实四页图像 PDF，经实际文件存储、生产 OCR 客户端及 PostgreSQL，外部 OCR HTTP 替身分别返回成功、失败、空结果及公式缺口，再通过公开 HTTP 核验页位、警告及受保护 PNG。

这两组测试已加入 `teaching-pr-http` CI，并要求报告非空、无失败、无错误、无跳过。浏览器脚本 `integration/teaching-ocr-real.spec.ts` 使用完整应用登录、上传和读取产品接口，不拦截产品 HTTP；以 `TEACHING_OCR_REAL_ONLY=true` 选择，需提供专用账户、扫描样例路径及配置好的外部 OCR/embedding 服务。

自编扫描样例和确定性模型只能证明处理与核对流程，不代替真实人教版教材、真实 OCR 模型和教师复核的最终验收。

# 第 3 课：从用户视角体验系统（小白版）

## 这节课要做什么

前两课我们完成了两件事：

1. 知道 AgentX 是一个智能体平台。
2. 用 Docker 把 AgentX 跑起来。

这一课先不看源码，也不讲复杂技术。

我们只从“普通用户”的角度体验系统：

```text
打开网页
  -> 登录账号
  -> 看懂首页
  -> 进入后台
  -> 认识 Agent、工具、知识库、模型这些入口
  -> 初步理解这些页面背后分别对应什么功能
```

这一课的目标是：

```text
先会用，再去读代码。
```

如果你连系统页面都没看熟，后面直接读源码会很痛苦。先把产品跑一遍，后面看代码时你才知道每个模块到底在服务哪个功能。

## 本课学习目标

学完本课后，你应该能做到：

1. 打开 AgentX 前端页面。
2. 使用默认账号登录。
3. 知道普通用户页面和后台管理页面的区别。
4. 大致知道 Agent、模型、工具、知识库分别是什么。
5. 能说出一次使用 AgentX 的基本流程。
6. 能把页面功能和后续源码模块建立初步对应关系。

## 开始前确认项目已经启动

先打开 PowerShell，执行：

```powershell
docker ps
```

如果看到：

```text
agentx   Up ... healthy
```

说明项目正在运行。

如果没有运行，可以执行：

```powershell
docker start agentx
```

然后等几十秒，再打开网页。

## 打开前端页面

在浏览器中打开：

```text
http://localhost:3000
```

这里再复习一下：

- `localhost` 表示你自己的电脑
- `3000` 是前端页面的端口
- 这个地址就是 AgentX 的主页面

如果页面打不开，优先检查：

```powershell
docker ps
docker logs --tail 100 agentx
```

## 普通用户页面和后台页面的区别

你可以先这样理解：

```text
普通用户页面：用系统
后台管理页面：管理系统
```

### 普通用户页面

普通用户页面主要用于：

- 浏览 Agent
- 创建自己的 Agent
- 和 Agent 对话
- 管理自己的工具
- 管理自己的知识库
- 配置自己的模型服务商
- 查看自己的 API Key 或账号信息

常见地址大概是：

```text
http://localhost:3000/explore
http://localhost:3000/agents
http://localhost:3000/tools
http://localhost:3000/knowledge
http://localhost:3000/settings
```

不同版本页面路径可能略有不同，但大方向类似。

### 后台管理页面

后台管理页面主要用于：

- 管理用户
- 审核 Agent
- 管理工具
- 管理模型服务商
- 管理订单和商品
- 管理 RAG 审核
- 管理系统规则

后台地址是：

```text
http://localhost:3000/admin
```

它会自动跳到：

```text
http://localhost:3000/admin/users
```

这说明后台默认先进入用户管理页面。

## 认识 AgentX 中最重要的几个词

在体验页面之前，先认识几个核心概念。

### 1. Agent

Agent 可以理解成：

```text
一个被设置好人设、能力和工具的 AI 助手。
```

比如：

- 写作助手
- 编程助手
- 客服助手
- 知识库问答助手
- 数据分析助手

每个 Agent 可以有自己的：

- 名字
- 头像
- 介绍
- 系统提示词
- 使用的模型
- 可调用工具
- 可访问知识库

### 2. 模型

模型就是背后真正生成回答的 AI。

例如：

```text
OpenAI 的模型
Anthropic 的模型
其他兼容 OpenAI 协议的模型
```

你可以这样理解：

```text
Agent 是角色设定。
模型是大脑。
```

Agent 告诉模型：

```text
你要扮演什么角色，用什么方式回答。
```

模型负责真正生成文字。

### 3. 工具

工具就是 Agent 可以调用的外部能力。

例如：

- 查询天气
- 读取网页
- 调用某个 API
- 操作文件
- 查询数据库
- 调用 MCP 工具

普通聊天只能“说话”。

有工具的 Agent 可以“做事”。

### 4. 知识库

知识库就是你上传给 Agent 的资料。

例如：

- 产品说明书
- 公司制度
- 课程讲义
- PDF 文档
- FAQ 问答

Agent 回答问题时，可以先从知识库里找相关内容，再基于这些内容回答。

这就是后面要学的 RAG。

### 5. 记忆

记忆是 Agent 对用户长期信息的保存。

比如：

- 你喜欢简洁回答
- 你的职业背景
- 你正在学习某个项目
- 你常用的表达习惯

知识库更像“资料库”。

记忆更像“用户档案”。

## 第四步：理解“创建 Agent”的大致流程

不同版本的页面细节可能不完全一样，但创建 Agent 的基本思路是类似的。

通常流程是：

```text
进入 Agent 页面
  -> 点击创建 Agent
  -> 填写名称、描述
  -> 设置系统提示词
  -> 选择模型
  -> 选择工具或知识库
  -> 保存
  -> 开始对话
```

我们先用生活例子理解。

如果你要创建一个“英语老师 Agent”，你可能会配置：

```text
名称：英语学习助手
描述：帮助我练习英语表达
系统提示词：你是一名耐心的英语老师，用简单中文解释英文语法
模型：选择一个可用的大模型
工具：暂时不选
知识库：暂时不选
```

保存后，这个 Agent 就变成了你的专属 AI 助手。

## 什么是系统提示词

系统提示词可以理解成：

```text
给 AI 的角色说明书。
```

例如：

```text
你是一名耐心的编程老师，面向零基础学生讲解概念。
回答时要使用生活类比，避免堆砌术语。
```

这段话会影响 AI 的回答风格。

同一个模型，加上不同系统提示词，就能变成不同 Agent。

比如：

```text
同一个模型 + 法律顾问提示词 = 法律助手
同一个模型 + 英语老师提示词 = 英语老师
同一个模型 + Java 老师提示词 = 编程老师
```

## 第五步：发起一次对话

创建或选择一个 Agent 后，就可以开始聊天。

一次普通对话看起来很简单：

```text
你输入一句话
Agent 返回一段回答
```

但系统背后其实做了很多事：

```text
前端发送消息
  -> 后端接收请求
  -> 找到当前用户
  -> 找到当前会话
  -> 找到当前 Agent
  -> 读取 Agent 配置
  -> 读取历史消息
  -> 调用模型
  -> 流式返回结果
  -> 保存聊天记录
```

这一条链路，就是后面课程最重要的源码主线。

## 第六步：观察浏览器请求

这一步不是必须，但建议你慢慢熟悉。

在浏览器里按 `F12`，打开开发者工具。

找到：

```text
Network
```

这个面板会显示网页向后端发出的请求。

你现在只要知道：

```text
前端页面不是自己完成所有事情。
它会不断向后端 API 发请求。
```

比如：

- 登录时会请求后端
- 获取 Agent 列表会请求后端
- 发送聊天消息会请求后端
- 后台用户列表会请求后端

后面学源码时，我们会把这些请求和 Java Controller 对起来。

## 页面和源码的简单对应关系

现在先记住一个粗略对应表。

| 你看到的页面 | 大概对应的前端目录 | 大概对应的后端模块 |
| --- | --- | --- |
| 登录页面 | `agentx-frontend-plus/app` | `auth` / `user` |
| 探索页 | `explore` 相关页面 | `agent` |
| Agent 管理 | `agents` 相关页面 | `domain/agent` |
| 聊天页面 | chat 相关组件 | `conversation` |
| 工具页面 | `tools` 相关页面 | `tool` |
| 知识库页面 | `knowledge` / `rag` | `rag` |
| 后台用户管理 | `admin/users` | `admin/user` |
| 后台模型管理 | `admin/providers` | `llm` |
| 后台订单管理 | `admin/orders` | `order` / `payment` |

这个表不要求背。

你只要先有感觉：

```text
每个页面背后都有前端代码。
每个操作背后都有后端接口。
每个接口背后都有业务模块。
```

## 如果页面提示没有权限

如果你访问后台页面时提示没有权限，通常说明：

```text
你没有用管理员账号登录。
```

解决：

1. 退出当前账号。
2. 用管理员账号登录。

管理员账号：

```text
admin@agentx.ai / admin123
```

## 如果页面里没有数据

这不一定是错误。

因为你是刚启动的新系统，很多数据可能还没有创建。

你可以先理解：

```text
空列表说明数据库里暂时没有对应数据。
```

例如：

- 没有用户创建 Agent，Agent 列表可能为空。
- 没有订单，订单列表可能为空。
- 没有上传知识库，知识库列表可能为空。

空页面也是正常状态。

## 这节课不要急着配置模型

你可能会发现，真正和 Agent 对话需要配置模型服务商。

如果暂时没有可用 API Key，不用着急。

这一课的重点不是让模型一定能回答，而是让你先看懂：

```text
系统有哪些页面
每个页面大概负责什么
普通用户和管理员有什么区别
AgentX 是怎么组织功能的
```

模型配置会在后面的课程单独讲。

## 本课小结

这一课我们从用户视角认识了 AgentX。

你需要记住：

```text
AgentX 有普通用户页面，也有后台管理页面。
普通用户页面负责使用系统。
后台管理页面负责管理系统。
Agent 是被配置好的 AI 助手。
模型是 Agent 背后的大脑。
工具让 Agent 能做事。
知识库让 Agent 能基于资料回答。
记忆让 Agent 能长期记住用户信息。
```

更重要的是，你要建立一个感觉：

```text
页面上的每个按钮，背后都有一条请求链路。
后面我们读源码，就是把这些请求链路一条条拆开。
```
